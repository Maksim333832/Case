# ADR-0003: Изоляция секретов, AI-валидация и детерминированный fallback

- **Статус:** Принято
- **Контекст:** В настройках нод хранятся токены Telegram/Webhook/LLM, а исходники содержат встроенные секреты. LLM может галлюцинировать пути, номера строк или несуществующие CVE.
- **Решение:**
  1. Все секреты `credentials` шифруются Fernet (`APP_SECRET_KEY` или ключ вне репозитория с правами `0600`). API возвращает только `"****"` + 2–4 последних символа.
  2. `SecretMaskingFilter` и `mask_text` очищают логи, исключения, `output_preview`, WS-события и отчёты.
  3. В LLM передаются только маскированные `Finding`, никогда исходный код или сырые значения секретов.
  4. `app/nodes/ai/validator.py` проверяет JSON-схему, существование `finding_ref`, совпадение упомянутых файлов и строк, фильтрует выдуманные `CVE`/`GHSA`; при сбое выполняется 1 повторная попытка, затем детерминированный fallback-отчёт.
- **Последствия:** Платформа устойчива к сбоям и галлюцинациям LLM и гарантирует отсутствие утечек секретов во всех каналах.
