# ADR-0001: Реестр нод и собственный DAG Workflow Engine

- **Статус:** Принято
- **Контекст:** Платформа должна визуально конструировать сценарии (по аналогии с n8n/React Flow), но запрещено брать n8n/Node-RED за основу. Добавление новой ноды должно требовать создания одного файла без изменений в движке, API и фронтенде.
- **Решение:**
  1. Все ноды наследуют `BaseNode` (`type`, `label`, `group`, `inputs`, `outputs`, `Params`), декорируются `@register_node`.
  2. `app/nodes/registry.py` автоматически импортирует все модули внутри `app.nodes` через `pkgutil.walk_packages`.
  3. `GET /api/node-types` отдаёт порты и `Params.model_json_schema()`, по которым React Frontend автоматически строит палитру и форму параметров ноды.
  4. `app/engine/graph.py` и `executor.py` выполняют DAG в топологическом порядке на `asyncio` (блокирующие шаги — в `asyncio.to_thread`), поддерживают ветвление (`skipped` для неактивных веток), таймауты и изоляцию падений (`partial` / `failed`).
- **Последствия:** Добавление `notify.webhook` и `notify.smtp` выполнено созданием одного файла на ноду без правки движка, API или фронтенда.
